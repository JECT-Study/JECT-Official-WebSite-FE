# commit

이 저장소의 컨벤션에 맞춰 변경사항을 커밋한다. 핵심 목표는 변경 내용을 한국어 한 줄로 짧게 요약하되, 어떤 종류의 변경인지 prefix로 드러내고, 관련 없는 변경은 섞지 않는 것이다.

## 커밋 메시지 형식

```
<type>: <한국어 한 줄 요약>
```

- **type(영어 prefix)**: `feat` / `fix` / `refactor` / `chore` / `docs` / `style` / `test` / `build` / `ci` / `perf`
- **요약(한국어)**: 무엇을 바꿨는지 한 줄로. "~추가/~수정/~제거"처럼 자연스러운 한국어로. 마침표 없이.
- 한 줄이 원칙이다. 본문(body)은 왜 바꿨는지가 비자명할 때만 한 줄 띄우고 짧게 덧붙인다.
- 불필요한 footer(서명, 생성 표식 등)는 붙이지 않는다.

**예시**

| 변경             | 커밋 메시지                              |
| ---------------- | ---------------------------------------- |
| FAQ 페이지 포팅  | `feat: FAQ 페이지 마이그레이션`          |
| 딥링크 깨짐 수정 | `fix: FAQ 딥링크 진입 시 탭 미선택 수정` |
| PR 템플릿 추가   | `chore: PR 템플릿 추가`                  |
| 스모크 스펙 추가 | `test: 라우팅 스모크 스펙 추가`          |
| README 갱신      | `docs: 설치 안내 최신화`                 |

## 작업 순서

1. **변경 파악**: `git status`와 `git diff`(스테이징된 것은 `git diff --cached`)로 무엇이 바뀌었는지 먼저 본다. 추측하지 말고 실제 diff를 근거로 요약한다.
2. **단위 나누기**: 서로 다른 목적의 변경이 섞여 있으면 여러 커밋으로 나눈다. 특히 페이지 포팅과 API 연동 변경, 리팩토링은 반드시 분리한다(마이그레이션 원칙).
3. **스테이징**: 해당 커밋에 들어갈 파일만 `git add`. 전체를 무지성으로 `git add -A` 하지 않는다.
4. **커밋**: 위 형식으로 `git commit -m "..."`.
5. **훅 동작 확인**: pre-commit 훅(lefthook)이 staged 파일에 `eslint --fix` + `prettier --write`를 적용하고 자동 재stage한다. 훅 출력에 에러가 없는지 확인한다.

## 검증

- 코드(.ts/.tsx)를 바꿨다면, 커밋 전후에 `pnpm typecheck`를 실행해 타입이 깨지지 않았는지 확인한다(pre-push 훅에서 막히기 전에 미리 확인한다).
- 셸에 mise가 활성화돼 있지 않으면 `mise exec -- pnpm typecheck` 형태로 실행한다.
- 훅을 우회해야 하는 분명한 사유가 있을 때만 `git commit --no-verify`를 쓰고, 그 이유를 알린다.

## 주의

- `dev`와 `main`에 직접 커밋하지 않는다. 현재 브랜치가 둘 중 하나면 사용자에게 알리고 작업 브랜치를 만들 것을 제안한다.
- 커밋 메시지에 없는 변경을 지어내지 않는다. diff에 실제로 있는 것만 요약한다.
