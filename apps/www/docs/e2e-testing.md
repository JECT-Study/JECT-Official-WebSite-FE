# E2E 테스트 가이드

공식 홈페이지의 E2E는 Playwright로 작성합니다. 이 문서가 작성과 실행 방법의 단일
출처입니다.

## 테스트 범위

두 레이어로 구성합니다. 그 밖의 항목은 E2E로 다루지 않습니다.

1. **핵심 사용자 여정**: 지원 플로우(공고 목록, 안내, 퍼널 스텝, 제출 완료), 이어쓰기,
   PIN 재설정. 처음부터 끝까지 진행합니다.
2. **스모크와 라우팅 계약**: 모든 경로가 예외 없이 렌더되는지, 레거시 리다이렉트가
   동작하는지, 딥링크(`/faq/:tabId/:questionId`)와 404가 동작하는지 확인합니다.

소개 페이지 문구, 반응형 레이아웃, 애니메이션은 E2E로 검증하지 않습니다. 스크린샷 비교도
하지 않습니다. 시각 검증은 디자인 시스템의 VRT와 Chromatic이 담당합니다.

## 실행

```bash
pnpm e2e                    # 이 앱을 실행한 뒤 테스트
pnpm e2e:ui                 # UI 모드 (디버깅)
pnpm e2e:report             # 마지막 리포트 열기
pnpm e2e:codegen http://localhost:3000/apply   # 브라우저 조작을 녹화해 초안 생성
```

기존 앱이나 Vercel 프리뷰를 대상으로 같은 스펙을 실행할 수 있습니다.

```bash
# 기존 앱. 아직 이전하지 않은 경로까지 전부 검증
E2E_TARGET=legacy E2E_BASE_URL=http://localhost:5173 pnpm e2e

# Vercel 프리뷰
E2E_BASE_URL=https://<preview-url> pnpm e2e
```

`E2E_BASE_URL`을 지정하면 Playwright가 앱을 직접 실행하지 않습니다.

## 작성 규칙

- **셀렉터는 역할과 접근성 이름으로 지정합니다.** `getByRole("button", { name: "다음" })`
  형태를 사용합니다. CSS 클래스나 DOM 구조에 의존하지 않아야 디자인 시스템 버전을 올려도
  테스트가 유지됩니다. 이 지점에서 실패한다면 접근성 이름이나 role이 변경된 것이므로
  확인이 필요한 신호입니다.
- **콘텐츠 리터럴을 단정하지 않습니다.** 공고 정보처럼 서버에서 전달될 값은 "카드가 하나
  이상 존재한다", "첫 카드를 선택하면 해당 이름이 다음 화면에 표시된다"처럼 관계로
  작성합니다.
- **테스트는 서로 독립적으로 작성합니다.** 앞 단계를 UI로 반복하지 않고, 인증은
  `storageState` 픽스처로, 중간 시작 지점은 테스트용 API 호출로 준비합니다. 공용 준비
  동작은 `e2e/helpers/`에 모읍니다.
- **모킹은 통제할 수 없는 대상으로 한정합니다.** 외부 인증처럼 테스트 환경에서 실행이
  불가능한 것만 `page.route`로 가로챕니다. 백엔드 응답까지 모킹하면 E2E의 목적이
  사라집니다.
- **분석 스크립트를 차단합니다.** Sentry, Amplitude, Meta Pixel이 테스트 트래픽으로 실제
  데이터에 반영되지 않도록 막습니다.
- **단계는 `test.step`으로 묶습니다.** trace에서 실패 지점을 바로 확인할 수 있습니다.

## 경로 추가

`e2e/routes.ts`의 `ROUTE_CONTRACT`가 두 앱이 지켜야 할 URL 목록입니다. 페이지를 옮길
때마다 해당 항목의 `migrated`를 `true`로 변경합니다. 이 파일이 마이그레이션 진척도를
나타냅니다.

## 실패 분석

CI가 `playwright-report` 아티팩트를 남깁니다. 내려받아 열면 각 단계의 화면, 네트워크
요청, 콘솔 로그, 에러 스택을 확인할 수 있습니다.

```bash
pnpm exec playwright show-report <내려받은 경로>
```

로컬에서는 `pnpm e2e:ui`로 실패 지점을 재생하며 셀렉터를 확인하는 방법이 빠릅니다.
